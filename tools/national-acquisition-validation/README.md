# National validation protocol (non-production)

- Public-source probe: checks DPME metadata, feature counts, and representative search / exact ID resolution across nine provinces; public GET requests only. Sample codes are test expectations, not certified boundary assignments. A pass does not certify exhaustive/current township coverage. DPME municipality layer is labelled 2018. Use Statistics South Africa's current main-place/sub-place data and Municipal Demarcation Board's effective boundaries for a reviewed, versioned crosswalk before declaring nationwide authoritative coverage. Public references: https://dataportal-mdb-sa.opendata.arcgis.com/ and https://www.demarcation.org.za/municipal-boundaries/ .
- Emulator probe: exact localhost:8189, demo-teyza-national-validation, no cloud credentials, separate config, synthetic records only. Real Firebase Admin SDK exercises pagination, all-record counts, legacy history, code/category/municipality filters, paid seller/advertiser reconciliation, concurrent writes and fresh versus fixed snapshots. Page timings are local emulator measurements, not production SLAs or billed read estimates. No functions, auth, hosting or rules deployed; no outbound actions called.
- GitHub PR workflow keeps evidence in separate JSON artifacts and fails if a probe fails. Do not treat an inaccessible upstream service or failed snapshot check as passed. A failed emulator test may expose emulator limitations or an application defect; diagnose before release.
- Remaining independent cloud staging gate: explicitly approved, distinct non-production Firebase project, restricted synthetic data, current Firestore indexes and query plans, realistic concurrency, rate limits, latency/cost budgets and read-time retention, legacy collision review. Never substitute a production project for staging.
