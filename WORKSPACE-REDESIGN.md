# Business Expo workspace redesign

The 14 workspace pages share `assets/workspace.css`, `assets/workspace.js`, and the shell/navigation generated by `scripts/build-workspace.py`. Edit page bodies under `ui/pages/` and titles/scripts in `ui/pages.json`, then run:

```powershell
python scripts/build-workspace.py
```

The login, signup and password-reset pages use the same stylesheet. The old `assets/styles.css` is retained for the public landing page; workspace pages no longer load it. No page-specific stylesheet overrides the workspace shell.

## Profile save repair

- The submit handler attaches before asynchronous loading. Failed loads cannot send profile fields as a GET request.
- Saving stays disabled until the account context is known; load errors expose Retry loading.
- Existing activeBusinessId, businessId, businessIds and legacy owner fields are recognized.
- Missing initial workspace records can be created atomically with the user link. An inaccessible or missing linked business is not silently replaced.
- Failed saves preserve edits. Successful saves confirm in place and update the sidebar/profile summary.
- Ownership fields, billing plan and balances cannot be edited through the profile form.
- Dashboard orders/products load independently. Unavailable data is never displayed as zero.

## Deployment status

This change is local. It does not publish the website or change live Firebase rules.

The repository did not contain the deployed Firestore rules, so the exact live permission error could not be verified. `firestore.rules` and `firebase.json` now provide an owner-scoped rules configuration for the collections used by these screens. Compare it against the live rules and validate in a Firebase emulator/staging project before deployment. The profile/browser tests mock Firebase; they do not validate the deployed authorization policy.

For the configured Firebase project, the relevant deployment commands are:

```powershell
firebase deploy --project business-lift-3c19c --only firestore:rules
firebase deploy --project business-lift-3c19c --only functions
```

The server change recognizes `ownerUid` alongside the legacy ownership fields. Seller operations, bank details and OAuth credentials remain server-only. Do not replace their deny rules with browser access. Publish the generated HTML files and the assets/js directories through the existing website hosting process. Website hosting is not configured or changed by `firebase.json`.

## Validation

Run a local server with `python -m http.server 4173 --bind 127.0.0.1`, then `node tests/workspace-browser.cjs` on this development machine (bundled Playwright and local Chrome paths are specified in the test).

The browser suite checks all 14 workspace pages at 1440px and 390px, consistent navigation, active page state, mobile menu/Escape handling, absence of horizontal overflow, profile save success/failure/retry, and auth-page mobile layout. Screenshots under `tests/artifacts` use isolated test data, not a live account. Domains and website publishing were placeholders and are now labelled Coming soon; fabricated customers, payments and store statistics were removed.
