# Teyza Google Maps, Meta WhatsApp and Facebook Login — operator setup

## Map
Current Admin map uses the Google Maps JavaScript API in the browser and the existing backend Teyza Places service for nearby search. The server-side TEYZA_GOOGLE_PLACES_KEY is **not** a browser key. Maps JavaScript API must be enabled, billed, and available to the domain; the new UI detects missing/invalid keys, denied referrers, script failures and timeouts. Use the Google Cloud project business-lift-3c19c and create a new dedicated browser key with **Websites** restrictions on https://teyza.co.za/* and https://www.teyza.co.za/*, and **API restriction: Maps JavaScript API**. Copy the key into Admin > National shop map > Google Maps browser key, then click Open coverage map. Do not paste the Places server secret or unrestrict a service key. Refresh admin sidebar search if it filters navigation to an email address. Google-only results require a manual Search Google near map centre after the basemap loads; a national Google census is not provided.

## WhatsApp (Meta Cloud API)
Meta template teyza_seller_welcome_menu is Marketing and shown Active – Quality pending in screenshots. This is not a WhatsApp OTP authentication template or proof of API delivery. Verify approved component header IMAGE and exact ordered body placeholders in Meta WhatsApp Manager. Existing worker assumes (ownerFirstName,shopName) only when explicitly configured. Image must be reachable over HTTPS from teyza.co.za and match the approved template; do not upload customer-sensitive images.

A live WhatsApp Cloud API requires the **Phone Number ID** (not Meta App ID, WABA ID or template ID), a long-lived system-user token with whatsapp_business_messaging permissions and matching WABA access, and opt-in from the recipient. Firebase Secret Manager name is TEYZA_WHATSAPP_ACCESS_TOKEN. Configure non-secret env vars TEYZA_WHATSAPP_PHONE_NUMBER_ID, TEYZA_WHATSAPP_API_VERSION, TEYZA_WHATSAPP_TEMPLATE_NAME, TEYZA_WHATSAPP_TEMPLATE_LANGUAGE, TEYZA_WHATSAPP_TEMPLATE_HEADER_IMAGE, TEYZA_WHATSAPP_TEMPLATE_HEADER_IMAGE_URL, TEYZA_WHATSAPP_TEMPLATE_BODY_FIELDS and TEYZA_WHATSAPP_NOTIFICATIONS_ENABLED=1 **only when all requirements have been verified**. A dedicated opted-in test account must be the first recipient. The two optional Cloud Functions for WhatsApp are not deployed by the admin-only deploy runner. Do not put tokens into source, screenshots, PowerShell history or chat. Read admin diagnostics after worker deployment; provider accepted is not delivered, and uncertain sends are not blindly retried. Two-way messages and OTP login need separate webhook/authentication work.

## Facebook Login
Existing Flutter source contains a disabled Facebook bridge and the signed release workflow enables it only when **both** TEYZA_FACEBOOK_APP_ID (GitHub Actions repository variable) and TEYZA_FACEBOOK_CLIENT_TOKEN (GitHub Actions repository secret) are present at build time. The Meta app ID displayed in screenshots is not by itself proof of configured Facebook Login. Configure Facebook Login use case/product in the same Meta app (if appropriate), add Android package com.asiyedriver.asiye and actual signed QA / Play signing certificate key hashes, and iOS bundle za.co.teyza.shopper with required URL schemes. In Firebase project business-lift-3c19c Authentication > Sign-in method, enable Facebook and input Meta App ID and Meta App Secret (only in Firebase Console); add https://business-lift-3c19c.firebaseapp.com/__/auth/handler as a valid OAuth redirect URI in Meta Facebook Login settings. Check exact redirect URI from Firebase Console rather than guessing a custom auth domain. Meta App Secret belongs ONLY in the Firebase provider settings, never in Flutter or GitHub app-client token variable. Configure app mode and permissions for real public users, and test both platforms on physical devices with the signed build. A successful WhatsApp template approval does not enable Facebook Login.

Never use a Facebook/Google sign-in to transfer existing seller data to another Firebase UID. Test existing account continuity and explicit credential conflict handling.
