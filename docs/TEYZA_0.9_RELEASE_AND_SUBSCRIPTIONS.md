# Teyza Shopper 0.9 and Seller Subscriptions — Deployment

## What this update contains
- Shopper: automatic Android location discovery on startup/resume if permission has been granted, Spaza/Variety listing polish, directions, Chat tab, foreground unread badges, Firebase Google sign-in integration.
- Seller web: \`seller-subscriptions.html\` with Basic **R99/month** and **Plus/Sponsored prices by quotation**; linked from the landing page and seller dashboard.
- Backend: authenticated plan requests and admin-only activation after independently verified payment; catalogue displays Basic without product prices and Plus/Sponsored with verified inventory. Existing legacy merchants are unaffected.

## Website deployment (DirectAdmin 10hosting)
Backup your current \`public_html\` files first. Extract \`TEYZA_SHOPPER_0.9_WEBSITE_PATCH.zip\` into \`domains/teyza.co.za/public_html\`.
Included:
- \`index.html\`
- \`dashboard.html\`
- \`seller-subscriptions.html\`
- \`js/seller-subscriptions.js\`
- \`api/workspace.php\`
- \`api/shopper-catalog.php\`
- \`api/chat.php\`

These replace the corresponding files and do NOT include, modify or expose your private Google Places API key, merchant database, photo endpoint or existing Google Places discovery code.

File permissions: 0644 for PHP/HTML/JS; 0755 directories. Keep confidential merchant data out of public_html.

## Seller plan rules
- Basic: R99 per month, approved local business listing, shop photo and directions, contact/chat and service information; **no priced products** in shopper app.
- Plus: approved listing, genuine merchant-entered pricing and inventory. **Monthly price must still be decided.**
- Sponsored: Plus features and featured placement. **Monthly price must still be decided.**
- The UI records plan requests but does NOT yet charge sellers automatically. No recurring billing will start until Teyza has configured Paystack or another payment processor with secure server-side subscription initialization and webhook verification.
- Never activate from a client response. Admin-only \`admin-seller-subscription\` requires an independently verified payment reference, then grants a one-month period. The admin operation must ONLY be used after checking funds/transaction with the payment provider.
- For new workspaces subscription starts at \`not_selected\`; only active, non-expired subscriptions can appear publicly after company verification, opt-in and approval. Shops already approved before this rollout with no subscription record remain on their current legacy rules.

## Google sign-in — IMPORTANT: incomplete without OAuth setup
Native shopper Google sign-in is implemented, but Android requires:
1. Enable the **Google** provider in the existing **Teyza Firebase Authentication project**. This is NOT the businessExpo Places API key.
2. Create/configure the Firebase Android application package \`za.co.teyza.teyza_shopper\` and register SHA-1/SHA-256 fingerprints for the **actual app signing certificate**, not a temporary CI signing key.
3. Use the corresponding **Web OAuth client ID** (ends \`.apps.googleusercontent.com\`) as GitHub repository Actions variable \`TEYZA_GOOGLE_WEB_CLIENT_ID\`. This is a public client identifier, not a secret. Never expose a client secret.
4. Ensure Android app signature is consistent across builds (production signing keystore stored securely in GitHub encrypted secrets) before releasing app widely.
5. The Actions workflow passes the above variable at build time; without it, Google login shows a clear configuration warning and email/password still works.
6. Test sign-in and logout on a real Android device. A CI build passing DOES NOT verify OAuth success.

## Messages & notifications
- \`api/chat.php\` uses the existing seller chat backend. Shopper messages are enabled **only for verified Teyza participants**. Google-listed unclaimed businesses have no verified Teyza chat recipient.
- The Chat inbox and unread counts refresh while app is foregrounded (60 seconds) or reopened. **Push notifications/background alerts are NOT activated**; these require Firebase Cloud Messaging integration and server delivery.
- No fake orders or payments are generated by messages.
