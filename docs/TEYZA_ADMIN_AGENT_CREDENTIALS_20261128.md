# Admin-created Field Agent login

Candidate only. No live accounts created, setup emails sent or Firebase/Hosting/App Store changes made during development.

1. Admin > Agents & field team > Applications > Create or link agent login (also accessible from Users & access). Enter the agent's own email, name, contact phone, province and operating area. Confirm the applicant requested the account. Use Create new login for a new email; explicit Link existing account preserves the same Firebase UID, roles and sign-in provider. Never create a duplicate account or reset an existing account without a request.
2. New Firebase email/password login starts email-unverified with a server-generated, undisclosed random password. Firebase sends a standard setup/reset email so the agent chooses a password privately. The pending profile is saved before requesting email; if delivery or storage is not confirmed, inspect HR/Users before retrying. No setup email for linking. HR can send a requested password setup email again.
3. In HR, upload applicant-authorised ID/passport and CV using existing encrypted document flow; review both current documents and approve the pending application. Existing area assignment, suspension and review rules stay in force. No admin/support/seller privileges, automatic approval, reward or paid access granted.
4. Mobile app: Account > Agent or existing email sign-in. Use the invited email and chosen password. If an invited account is not verified, send verification email and check verification/approval. An approved matching UID opens Agent mode or the existing role chooser; pending/suspended/rejected agents cannot perform field work. Existing public Shopper/Business owner registration and social login remain unchanged. The minimal pre-verification status action is own-UID only; it never returns private application documents or confers permission.
5. Test on an authorised disposable account. Confirm email receipt, setup, verification, approval, agent visits and review, suspension, reactivation, and non-admin/other-agent denial. Do not create production accounts or send real email during automated QA. Scope any future backend deployment to teyzaMobile alone and any Admin Hosting publication to the reviewed Admin assets (including teyza-field-admin.js). Preserve all other functions, rules, payments, existing Places release and website paths. Use signed mobile QA builds before any store publication.
